# Environment Contract

**Status: IMPLEMENTED for validation and examples; PREPARED_ONLY for real secret injection.** Source of truth: `backend/src/config/env.ts`, `backend/.env.example`, `backend/.env.staging.example`, `frontend/src/lib/api/client.ts`, and `frontend/.env.staging.example`.

## Backend variables

| Variable                                                                                                          | Contract                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `NODE_ENV`                                                                                                        | `development`, `test`, or `production`. Staging uses production runtime semantics; no separate staging mode is needed.                                                                                                                             |
| `PORT`                                                                                                            | Integer 1–65535; default 4000.                                                                                                                                                                                                                     |
| `MONGODB_URI`                                                                                                     | Required `mongodb://` or `mongodb+srv://`; never log or place in frontend variables. Non-production rejects non-loopback hosts.                                                                                                                    |
| `MONGODB_DB_NAME`                                                                                                 | Required `[A-Za-z0-9_-]+`; passed explicitly as Mongoose `dbName`. Test name must contain `test`. Production semantics reject names with delimited `dev`, `development`, `test`, or `testing`; use a dedicated name such as `paniverse_lms_stage`. |
| `JWT_ACCESS_SECRET`                                                                                               | Required, at least 32 characters. Generate independently for staging and inject from the chosen secret manager.                                                                                                                                    |
| `JWT_ISSUER`                                                                                                      | Required absolute URL.                                                                                                                                                                                                                             |
| `JWT_AUDIENCE`                                                                                                    | Required non-empty string.                                                                                                                                                                                                                         |
| `ACCESS_TOKEN_TTL_SECONDS`                                                                                        | Integer 60–3600; default 900.                                                                                                                                                                                                                      |
| `SESSION_TTL_DAYS`                                                                                                | Integer 1–365; default 30.                                                                                                                                                                                                                         |
| `APP_ORIGINS`                                                                                                     | Comma-separated exact `http(s)` origins only; no wildcard, path, duplicate, or trailing slash. Production semantics require HTTPS.                                                                                                                 |
| `COOKIE_SECURE`                                                                                                   | `true`/`false`; must be true under production semantics.                                                                                                                                                                                           |
| `COOKIE_SAME_SITE`                                                                                                | `lax`, `strict`, or `none`; choose based on approved topology. Secure is required for production.                                                                                                                                                  |
| `PASSWORD_RESET_URL`                                                                                              | Optional absolute URL; required when any SMTP field is configured; HTTPS is required with production semantics.                                                                                                                                    |
| `SMTP_HOST`, `SMTP_PORT`, `SMTP_FROM`                                                                             | All required together when SMTP is enabled. Port is 1–65535.                                                                                                                                                                                       |
| `SMTP_USER`, `SMTP_PASSWORD`                                                                                      | Optional as a pair. Do not put either value in source/docs.                                                                                                                                                                                        |
| `MEDIA_S3_ENDPOINT`, `MEDIA_S3_BUCKET`, `MEDIA_S3_REGION`, `MEDIA_S3_ACCESS_KEY_ID`, `MEDIA_S3_SECRET_ACCESS_KEY` | All optional together; endpoint must be HTTPS with production semantics. Keep credentials private.                                                                                                                                                 |
| `MEDIA_SIGNED_URL_TTL_SECONDS`                                                                                    | Integer 60–900; default 300. Used by signed reads; upload intents currently use a fixed 600-second expiry.                                                                                                                                         |

## Frontend variables

- `VITE_API_BASE_URL` is read at Vite build time. It may contain the public API base URL only.
- `VITE_APP_NAME` appears in the local example.
- Never use a `VITE_` variable for MongoDB, JWT, SMTP, S3, or any other server credential: Vite values are public browser output.

## Staging mode decision

Keep the existing three-mode enum. Set `NODE_ENV=production` for staging to retain HTTPS cookie rules and permit the remote staging MongoDB host, while using a separate staging database, credentials, cluster/network rules, public origin, JWT secret, SMTP account, bucket, and runtime resources. Do not weaken the development/test loopback guard. Test scripts must run with test mode and a test-named local database; they cannot silently target staging or production.

The checked-in `.env.staging.example` files use only `.invalid` hosts and obvious replacement placeholders. They parse locally but are not deployable credentials.
