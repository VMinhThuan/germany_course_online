# API and Repository Mapping

## Contract baseline

Validated from `backend/openapi.yaml`: **75 paths and 96 operations**. The canonical source is `docs/backend-design/BE-00/openapi.yaml`; `backend/scripts/validate-openapi.ts` checks contract validity/synchronization. DTO interfaces live in `frontend/src/lib/api/types.ts`. Repositories: `public-repository.ts`, `student-repository.ts`, `admin-repository.ts` under `frontend/src/data/api/`.

Using the requested classifications: **95 operations are `ALREADY_INTEGRATED`; 1 (`getPublicMediaMetadata`) is `NOT_USED_BY_CURRENT_UI`; none require a missing adapter or UI.** The REST operations for media are integrated. The real upload/signing/playback capability is `BLOCKED_BY_EXTERNAL_PROVIDER` until an S3-compatible provider is configured; it is not a missing API adapter.

### Contract and money handling

- Pagination is consumed as `ApiPage<T>`; request query parameters are built with `URLSearchParams`.
- VND values remain decimal-string DTO values and are formatted for display. Checkout submits course/plan/coupon context, never client-calculated total or expiry.
- Write requests that support idempotency pass `Idempotency-Key`; API validation/business errors use `ApiError` and retain status/code/details/request ID.
- Cancelled/expired/revoked access, pending orders and coupon reservation behavior are read from backend state.
